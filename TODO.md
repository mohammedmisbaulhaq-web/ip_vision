# Project outcomes

- [x] **IP input and validated lookup.** The scanner accepts a blank input for the visitor’s public IP or a supplied IPv4/IPv6 address. Validate supplied addresses in the browser before any lookup request and show clear correction guidance for malformed values. Retrieve current live geolocation, network, and security indicators rather than showing demonstration data.
- [x] **Network identity and map card.** Present available IP identity, country, region, city, postal/ZIP code, timezone, coordinates, ISP, organization, autonomous-system details, and connection type in a distinct responsive result card. Show clear mobile, proxy/VPN-like, and hosting/data-center indicators. Use safe “Not available” fallbacks for absent fields. Generate a mapping-service link from returned coordinates when available.
- [x] **Clean View privacy mode.** Provide a Clean View toggle that hides ZIP/postal-code and organization details throughout the displayed results when enabled.
- [x] **Resilient accessible interface.** Provide clear loading and completion states, handle timeouts, offline/no-internet conditions, malformed/bad API responses and lookup failures with understandable messages, and keep the interactive layout polished, accessible, and responsive across desktop and mobile.
- [x] **Current-location distance and directions.** For results with valid geolocation coordinates, let the user request their current location after an explicit click. Calculate and show the straight-line distance from browser coordinates to the IP lookup location and provide a route link between the two coordinates. Identify the IP destination as approximate, explain that direct distance can differ from travel distance, request browser location permission only after the click, and handle denied or unavailable location access clearly. Keep the coordinates in the browser unless the user opens the external directions link.
- [x] **Web-name update.** Replace the old site name with `mizju_ipsearch` in the browser title, visible header and footer branding, accessible brand text, route metadata, and project documentation. Keep the scanner functions, visual mark, and existing page layout intact.
- [ ] **Feedback email delivery.** Add an accessible feedback section at the end of the page and deliver visitor submissions to the user's chosen verified inbox through Resend. Use one server-side email address as both the verified sender and recipient so there is no separate To-email setting or public recipient field. Keep the API key server-side, require a sender domain verified in Resend, and show clear submission success or failure status.
- [x] **One feedback submission per browser.** Persist a non-content submission marker before sending and disable the form after a successful send. If storage cannot be read or written, do not send. Clear the marker and allow retry only after a definite failure response; keep the form locked after an ambiguous outcome to avoid duplicate email. Store no feedback content in the marker.
- [x] **Feedback visual treatment.** Make the word “FEEDBACK” larger and highlighted, and give the feedback section its own distinct, high-contrast theme while keeping the form responsive and readable.
- [x] **Highlighted report/results theme.** Give the entire report/results output a more visually highlighted theme so the complete result stands out, while keeping report text readable and the design responsive.
